# Detecting missing or broken printed content: logical anomaly models, golden-template comparison, OCR/OCV

Scope reminder: white solid lettering ("betway", letters 30-60 mm tall) plus one small lot-code line on clear carrier film; 5 MP colour camera at about 0.17 mm/px; rectified images with small residual shift/rotation; 5-20 good images per SKU, many SKUs, no defect images. Baseline that fails: DINOv2 patch nearest-neighbour without position constraint (a missing letter looks like background, which is "normal" somewhere else in the image).

Reading notes on reliability:
- "(snippet)" means the fact comes from a search-result snippet and the page itself was not opened.
- LOCO numbers are image-level AUROC in percent. Different papers re-run baselines and report different values for the same method. Conflicts are listed, not resolved.
- Papers with arXiv IDs 2606.xxxxx and 2609.xxxxx are 2026 preprints, not yet peer-reviewed as far as I could tell.

## 1. Logical anomaly detection on MVTec LOCO AD: how the methods work, their numbers, and whether they are usable with 5-20 good images

### Takeaway
Top LOCO scores (about 95-97 mean AUROC: CSAD, SALAD, LogiCo, PSAD) come from methods that segment the image into components and then check component area/count/layout statistics, but they are trained per category on the full training set (hundreds of images, 1-1.5 h of training) or need part annotations. The training-free and few-shot ones (LogSAD, UniVAD, LogicAD, SAM-LAD, SINBAD, the Sept-2026 calibrated-fusion method) are weaker (about 71-92) and lean on heavy foundation models (SAM, GPT-4V/4o, Grounding DINO), with latency from 0.1 s to several seconds per image. For a fixed-position label none of them is a direct fit, but their core idea carries over: turn the image into a component map and compare component statistics per location.

How each works:
- GCAD: global-local knowledge distillation; the global branch has a low-dimensional bottleneck that learns global context and semantic constraints. — [LogiCo](https://arxiv.org/html/2606.28688)
- GCAD's branches each need a lot of data to learn the latent features, which the LogicAD authors call "a limitation in few-shot scenarios". — [LogicAD](https://arxiv.org/pdf/2501.01767)
- EfficientAD: teacher, student and an autoencoder; logical anomalies show up as a disagreement between two networks of different capacity (the autoencoder's bottleneck cannot reproduce invalid global layouts). Millisecond latency: 1.9 ms, 2369.8 img/s on an RTX 3090 as measured in the CSAD paper. — [LogiCo](https://arxiv.org/html/2606.28688); [CSAD](https://arxiv.org/html/2408.15628)
- PUAD: fits a Gaussian to the mean feature vectors of EfficientAD student feature maps and scores with Mahalanobis distance; it ignores spatial layout, so it catches "wrong amount of something" but not "wrong place". — [SALAD](https://arxiv.org/html/2509.02101); [LogiCo](https://arxiv.org/html/2606.28688)
- SINBAD: aggregates sets of local elements into permutation-invariant descriptors; good on logical anomalies but has no explicit count notion. — [Calibrated fusion](https://arxiv.org/html/2609.05091v1)
- ComAD: clusters DINO features into a rough segmentation, extracts per-component features (handcrafted region features) and compares them with a memory bank. — [CSAD](https://arxiv.org/html/2408.15628); [SALAD](https://arxiv.org/html/2509.02101)
- PSAD: few-shot part segmentation trained from human-annotated label maps, then three memory banks (patch, class histogram, composition). Top logical score (98.1) but needs manual masks. — [CSAD](https://arxiv.org/html/2408.15628)
- CSAD: RAM++ tags, Grounded-SAM and SAM-HQ produce pseudo-labels from normal images only; a light DeepLabV3+ decoder on WideResNet-50 is trained on them (with "logical synthetic anomalies" that paste extra components); at inference a patch-histogram branch splits the predicted segmentation map into grid cells and compares class histograms with normal statistics via Mahalanobis distance; an EfficientAD-style local/global student branch covers structural defects; the two scores are normalised separately and summed. 8.9 ms latency, 321.8 img/s on RTX 3090. Tags were manually filtered and some settings are category-specific. — [CSAD](https://arxiv.org/html/2408.15628)
- SAM-LAD: SAM segments query and reference images (per-category area thresholds); each object gets a descriptor from DINOv2-S features upsampled 8x by FeatUp; an optimal-transport matcher (SuperGlue-style Sinkhorn) pairs query objects with reference objects; unmatched objects are flagged; matched ones are scored by Mahalanobis distance to a per-position Gaussian. Uses k=2 nearest normal images from a template bank. 8.9 FPS on an A100. Fails when several objects of the same category are present (pushpins) and when SAM granularity is off. — [SAM-LAD](https://arxiv.org/html/2406.00625)
- SALAD: three branches. Local appearance (EfficientAD-based), global appearance (per-class mean features with a Gaussian), and a composition branch trained on "composition maps" (DINO features clustered with K=6, SAM-HQ masks labelled by majority cluster, a UNet distilled from these pseudo-labels). The composition branch is a reconstruction + discriminator pair trained with synthetic anomalies, including component removal and component inpainting. 64.6 ms per image; 65.1 M parameters; 70,000 iterations. — [SALAD](https://arxiv.org/html/2509.02101)
- LogSAD: GPT-4V reads a few normal images plus the category's written logical constraints once, offline, and outputs "interests" (objects/regions) and matching rules. At run time: patch matching against a memory bank (nearest neighbour), interest matching (SAM masks, pooled features, Hungarian matching against normal interest sets), and composition matching (CLIP checks each rule, binary result). Scores are standardised with normal validation statistics, passed through a sigmoid and fused by max. Few-shot results: 78.5 (1-shot), 82.1 (2-shot), 86.3 (4-shot) overall AUROC versus PatchCore 64.9 / 65.4 / 68.7, WinCLIP+ 68.0 / 69.7 / 71.3, PromptAD 71.2 / 72.6 / 73.5. — [LogSAD](https://arxiv.org/html/2503.18325v1)
- LogicAD: one normal image. Grounding DINO crops regions of interest, GPT-4o describes them with a guided chain-of-thought prompt (run K=3 times, outliers removed with LOF on text embeddings), an LLM formats the text to JSON, and the anomaly score is 1 minus cosine similarity between the normal and query text embeddings. An optional logic reasoner translates to first-order logic and uses the Prover9 theorem prover to give an explanation. Logical-only one-shot AUROC 86.0, F1-max 83.7; structural AUROC 81.5 (below PatchCore's 89.3 in the same table). Stated limits: results vary between VLMs (LLaVA 1.5: 73.3, LLaVA 1.6: 76.2 AUROC), inference takes "a few seconds per image", prompts need manual tuning, and GPT-4o counting accuracy drops fast as the number of identical objects grows. — [LogicAD](https://arxiv.org/pdf/2501.01767)
- UniVAD: RAM + Grounded-SAM produce component masks, refined by K-means on features; patches are matched only against reference patches of the same component (structural), and a graph over component features plus geometric features (area, colour, position) scores logical anomalies; equal-weight fusion. About 0.7 s per image; the authors say reliance on RAM, Grounding DINO and SAM "limits its applicability in real-time scenarios". 1-shot LOCO: UniVAD 71.0 vs PatchCore 62.0, ComAD 62.2, WinCLIP 58.0, AnomalyGPT 60.4. — [UniVAD](https://arxiv.org/html/2412.03342v2)
- LogiCo (June 2026): open-vocabulary segmentation with DINOv3 text-image similarity assigns each patch to a component class; a component-level reconstruction network, a patch-level structural reconstruction network and a small U-Net "segmentation map discriminator" are trained jointly on normal images with four synthetic manipulations of the segmentation map (deletion, replacement, addition, erasure). 17.4 img/s on an RTX 5090. All experiments use full training sets; no few-shot results. — [LogiCo](https://arxiv.org/html/2606.28688)
- Calibrated fusion (Sept 2026): five frozen branches (DINOv2 ViT-L set descriptors, pixel branch, DINOv2 patch memory, Wide-ResNet50 patch memory, SAM3 open-vocabulary counting). Each raw score is divided by its 99th-percentile score on normal images, then fused with a p-norm soft-OR (p=6). No gradient training, no LLM, no part labels; the only per-category input is a short list of concept names to count. 0.3-1.2 s per image (83 ms for the two backbones, 0.27 s per counted concept). — [Calibrated fusion](https://arxiv.org/html/2609.05091v1)

### Inferences
- The reason plain patch nearest-neighbour misses a missing letter is the same reason PatchCore scores only about 74-80 on LOCO logical anomalies: each patch is individually normal. Every method that fixes this adds either a global/layout representation (GCAD, EfficientAD autoencoder, PUAD, SINBAD) or an explicit component map with area/count statistics per region (ComAD, PSAD, CSAD, SALAD, LogiCo, SAM-LAD, UniVAD).
- LOCO objects move around (pushpins in compartments, screw bags), so those methods are built to be position-tolerant. This label is the opposite case: rectified, near-fixed pose. The cheap equivalent of CSAD's "patch histogram of the segmentation map per grid cell" is a per-location comparison of the letter mask with a reference mask. The foundation-model machinery (SAM, RAM++, GPT-4V) solves a segmentation problem that white-on-clear lettering mostly does not have.
- Practicality with 5-20 images per SKU and many SKUs: the trained methods (CSAD, SALAD, LogiCo, EfficientAD, GCAD, PUAD) are designed around the full LOCO training sets and per-category training of 1 h or more; nothing in the sources shows they hold up with 5-20 images. The only published few-shot evidence is LogSAD (86.3 at 4-shot), UniVAD (71.0 at 1-shot), LogicAD (86.0 logical at 1-shot), and those numbers are far below what an inspection station needs.
- VLM-based reading of the scene (LogicAD, LogSAD's rule check) costs seconds per image, depends on a cloud model (GPT-4V/4o) in the published versions, and has known counting failures. Not suitable as the in-line decision; possibly useful offline for generating rules.
- A cheap fix for the current baseline that follows directly from UniVAD's component-aware patch matching and SAM-LAD's per-position Gaussian: restrict the nearest-neighbour search to reference patches at the same (or neighbouring) position. With rectified images this alone should make "background where a letter should be" score as anomalous. This is PaDiM/position-constrained PatchCore behaviour; I did not find a LOCO number for exactly this variant.

### Gaps
- I did not open the original GCAD, EfficientAD, PUAD, SINBAD, THFR, ComAD or PSAD papers; their descriptions and numbers come from later papers' related-work sections and comparison tables.
- LOCO training-set sizes (I recall about 335-372 normal images per category) were not re-verified in this session.
- No logical/structural split found for THFR. No LOCO numbers found for few-shot settings between 5 and 20 images for any method.
- The calibrated-fusion paper does not state how many normal images it uses for calibration.
- No benchmark found that is specifically about missing printed characters; LOCO has no printed-text category.

## 2. Golden template / reference-based print inspection: classical pipeline, failure modes, and how industry tools handle them

### Takeaway
The standard recipe is: register the test image to a master, compare pixel-wise against a per-pixel tolerance, then filter the difference blobs by size and shape. Its known weakness is false alarms along edges from residual misregistration and local stretching, and vendors answer it in three ways: wider tolerance where the gradient is high (HALCON variation model), local "flex" warping of the model before subtraction (Cognex Flexible Flaw Detection), and comparing edges as edges with distance/angle tolerances and explicit "missing" and "extra" edge reports (Cognex boundary comparison). All of these train from one or a few good images, which matches the 5-20 images per SKU constraint.

### Cited Findings
- HALCON variation model: the model holds an ideal image and a variation image. In "standard" mode the ideal image is the mean of the training images and the variation image their standard deviation (can be trained iteratively, but is not robust to outliers). In "robust" mode they are the median and a scaled median absolute deviation (all images must be trained in one call). — [MVTec create_variation_model](https://www.mvtec.com/doc/halcon/2311/en/create_variation_model.html)
- HALCON "direct" mode is for a single training image: the ideal and variation images are supplied by the user through prepare_direct_variation_model, and because variation is typically large at object edges, edge operators such as sobel_amp should be used to build the variation image. — [MVTec create_variation_model](https://www.mvtec.com/doc/halcon/2311/en/create_variation_model.html)
- HALCON alignment requirement: "It is essential that the training images show the objects in the same position and rotation"; otherwise find the pose with shape matching and correct it with affine_trans_image. If only one image is available, an alternative to direct mode is to create synthetic variations (shift the image by a pixel or so, apply grey-value morphology) and train on those. — [MVTec create_variation_model](https://www.mvtec.com/doc/halcon/2311/en/create_variation_model.html)
- HALCON thresholds: prepare_variation_model converts the ideal and variation images into two threshold images. AbsThreshold (default 10, suggested 0-50) is the minimum absolute grey difference; VarThreshold (default 2, suggested 1-5) multiplies the variation image. Each can take two values, one for too-bright and one for too-dark deviations. compare_ext_variation_model can return only too-bright errors, only too-dark errors, or both as separate regions. — [MVTec prepare_variation_model](https://www.mvtec.com/doc/halcon/2311/en/prepare_variation_model.html)
- The widely copied HALCON print-check example uses prepare_variation_model(model, 20, 3), aligns each image to the reference pose by shape-based matching, and restricts the check to a region of interest because print-position variation otherwise produces false regions at borders. (snippet, third-party copy of the MVTec example) — [CSDN copy of the HALCON example](https://blog.csdn.net/yijiangyi/article/details/123846318)
- Cognex golden template comparison patent (1990s): test and template must be registered before subtraction, with a whole-pixel stage followed by a sub-pixel stage; the threshold image is a linear mapping of a standard-deviation image derived from sample images, so that normal variation including scene misregistration is tolerated. (snippet) — [US5640200](https://patents.google.com/patent/US5640200)
- Cognex's own later patent states the limit of GTC: it is "problematic at the boundaries of the objects being inspected, since the image data along edges is often unreliable." — [US6381366](https://patents.google.com/patent/US6381366)
- Cognex boundary point-based comparison: find boundary points in the run-time image and in the pattern, pair points that lie within a set distance after alignment (about one pixel up to ten pixels or more), accept a pair when angle (example 5-10 degrees) and contrast (example 10-20 percent) are close, and sort points into matches, extras and missing; connectivity analysis groups points into features that are reported as matching, extra or missing. — [US6381366](https://patents.google.com/patent/US6381366)
- Cognex In-Sight Flexible Flaw Detection: trains from a golden image; "Area inspections verify whether there are defects such as scratches or stains on the surface"; edge inspections report missing edge defects ("a previously trained Edge Segment is not found in the acquired image") and extra edge defects; FlexFlawModel lets the model be "stretched" to absorb displacement of edge pixels caused by positioning, lens or registration errors; masked pixels never generate a defect; area defects come from a residual image against the model and mask images. — [Cognex In-Sight Flaw Detection docs](https://docs.cognex.com/isvidi_161/web/en/help_isvidi/content/topics/Spreadsheet/VisionTools/FlawDetection.htm)
- Cognex PatInspect (VisionPro): compares a region against a template trained from one or more defect-free images, built on PatMax so it tolerates rotation and scale change, and analyses intensity differences and boundary differences separately. (snippet, 1998 product listing) — [Photonics.com listing](https://www.photonics.com/Product.aspx?PRID=2702)
- Issues that decide whether golden-template comparison works: illumination and contrast variation, sub-pixel misregistration, grey-level versus geometric/morphological defect criteria, and training the template from real samples; sub-pixel interpolation is done before subtracting. (snippet) — [Quality Magazine, change detection for machine vision](https://www.qualitymag.com/articles/91534-change-detection-for-machine-vision-applications)
- HP's legacy variable-data print inspection system is a documented example of the classical chain: convert the reference to the scanner colour space, detect page corners, global block matching then local template matching (because "paper movement causes local and global spatial distortions"), histogram matching for colour, multi-scale SSIM comparison patch by patch, then filter each candidate by size/contrast/shape (minimum defect about 1 mm squared), optionally a VGG16 classifier on each candidate to cut false alarms. — [Haik et al., WACV 2020](https://arxiv.org/pdf/2001.04325)
- Same paper on the weakness: subtraction and thresholding "tends to be very sensitive to noisy changes (such as misregistration errors)" and "does not work well without significant pre/post-processing"; the same holds for SSIM. Measured: the legacy system had 0.5% false alarms and 30% missed defects. — [Haik et al., WACV 2020](https://arxiv.org/pdf/2001.04325)
- Print-proofing software (GlobalVision) overlays a scanned sample on the approved master for pixel-level comparison and flags misregistration, missing graphics and broken text. (snippet) — [GlobalVision graphics inspection](https://globalvision.co/artproof.php)

### Inferences
- With 5-20 rectified good images per SKU, a HALCON-style variation model (median + MAD, or mean + std) is directly buildable and has no training cost, so it scales to many SKUs. The clear film's stretch means a single rigid alignment for the whole label may leave residual error at the far letters; aligning per letter (or per block) before comparison is the usual answer and is what "flex"/local template matching does.
- Solid white letters on clear film are close to a binary scene. The dominant pixel population after alignment is "letter interior" and "background", both stable; only a 1-3 px band along edges is unstable. A tolerance band along edges (variation image from a Sobel magnitude, or a dilated edge mask) removes most false alarms but also hides nicks smaller than the band. At 0.17 mm/px, a 2 px band means nicks under roughly 0.3-0.4 mm are not detectable by differencing. Edge-based comparison (missing/extra edge points with distance tolerance) is the tool designed for that residual band.
- Using separate too-bright and too-dark outputs maps well to the defect types: "too dark where the reference is white" = missing letter or missing part; "too bright where the reference is background" = extra material, smear or adhesive residue.
- The appearance of clear film depends on what is behind it. A golden template built on one background will not transfer if the backing or lighting changes, so the mask-level comparison (section 4) is likely more stable than raw grey-value comparison.

### Gaps
- The exact formula for the HALCON threshold images did not survive page extraction. From my memory of the same page it is upper = ideal + max(AbsThreshold_bright, VarThreshold_bright x variation) and lower = ideal - max(AbsThreshold_dark, VarThreshold_dark x variation); verify against the page before quoting.
- No documentation retrieved for EyeC, ISRA Vision, AVT/Esko, Keyence or Zebra Aurora print-inspection tools (the search returned only GlobalVision and similar proofing vendors). How those systems handle web stretch and register tolerance is unsourced here.
- No HALCON documentation retrieved for its dedicated OCV or newer deep-learning print-inspection features.
- No source found that deals with golden-template comparison on transparent film specifically.

## 3. Learned reference comparison (Siamese / change detection / registration-based few-shot AD): is feature-level differencing better than pixel differencing?

### Takeaway
There is one solid quantitative comparison (HP's print-inspection study): fusing reference and test at the feature level with a Siamese detector cut false alarms from 0.5% to 0.005% and misses from 30% to 10% versus the classical SSIM pipeline, and feeding a raw pixel difference into the same detector was far worse (30-35% false alarms). But that system and the other Siamese template-comparison networks are trained on thousands of labelled defect pairs, which this project does not have. The good-only versions of the idea are registration-based few-shot AD (RegAD/CAReg) and frozen-backbone feature comparison at matching positions.

### Cited Findings
- HP variable-data print inspection, labelled set of 20,000 image pairs with 40,000 real defects, 4-fold cross-validation. False alarms % / missed defects % / seconds per sample: Legacy (registration + SSIM + rules) 0.5 / 30 / 0.90; Legacy + VGG16 classifier 0.050 / 32 / 1.00; FlowNet2 + pseudo-colour SSD (early fusion) 0.010 / 15 / 0.25; FlowNet2 + CD-SSD (middle feature fusion) 0.005 / 10 / 0.30; FlowNet2 + 6-channel concatenation + SSD 0.020 / 35 / 0.25; FlowNet2 + multi-spectral Siamese SSD 0.015 / 23 / 0.30; FlowNet2 + pixel DIFF + SSD 30 / 22 / 0.25; SSD on the scanned image alone, no reference, 55 / 48 / 0.07. — [Haik et al., WACV 2020](https://arxiv.org/pdf/2001.04325)
- On an unlabelled test set of 80,000 real print pairs (false alarms only): Legacy 0.5%, Legacy + classifier 0.1%, pseudo-colour SSD 0.010%, CD-SSD 0.005%, pixel DIFF + SSD 35%, single-image SSD 60%. — [Haik et al., WACV 2020](https://arxiv.org/pdf/2001.04325)
- Design reasons given: fuse first at conv4_3 "since it has a relatively large receptive field which is more robust to misregistration errors"; concatenating the two grey images is "more robust to misregistration errors compared to taking the difference between them"; a difference image "is more sensitive to noise and misregistration errors". — [Haik et al., WACV 2020](https://arxiv.org/pdf/2001.04325)
- The same study replaced local template matching with FlowNet2 optical flow for registration because the page is stretched randomly and locally by the transport; it reports a maximum error of a few pixels. — [Haik et al., WACV 2020](https://arxiv.org/pdf/2001.04325)
- Printed-label specific: a triple-stream Siamese segmentation network (IEEE TIM 2024) builds a pretrained registration module into the network to handle large deformation between template and sample, and reports +4.20% F1 and +7.51% IoU over prior methods. (snippet) — [Triple-stream Siamese network for printed label defect detection](https://www.bohrium.com/paper-details/triple-stream-siamese-segmentation-network-for-printed-label-defect-detection/1063163723918606362-3916)
- A change-aware Siamese network treats defect finding as change detection for steady but complex backgrounds such as PCBs and printed matter, using feature discrepancies in the decoder to localise defects. (snippet) — [Change-aware Siamese network, arXiv 2409.00589](https://web3.arxiv.org/pdf/2409.00589)
- BGNet (template-sample comparison for surface-mounted devices) uses a Siamese network with Transformer attention to cope with background variation between template and sample; it notes that Siamese U-Net subtracts template features from sample features at several layers. (snippet) — [BGNet](https://ntongzhi.github.io/publication/BGNet.pdf)
- CoNet combines template-matching style comparison with deep semantic features for print defects and reports 99.1% mAP on DeepPCB. (snippet) — [CoNet, Journal of Computer Applications 2023](https://www.joca.cn/EN/Y2023/V43/I1/250)
- NVIDIA TAO Visual ChangeNet-Classification is a ready Siamese transformer that takes a golden reference image and a test image of a PCB component and outputs defect / no defect; it is meant to be fine-tuned from pretrained weights. (snippet) — [NVIDIA NGC model card](https://catalog.ngc.nvidia.com/orgs/nvidia/tao/models/visual_changenet_classification/-)
- RegAD (ECCV 2022 oral): few-shot AD with registration as the proxy task. A Siamese network with three spatial-transformer blocks is trained once, category-agnostic, with a feature-level registration loss (cosine similarity) instead of pixel-wise registration; at test time, registered features of the test image are compared with those of the few normal support images. Claims 3-8% AUC gain over earlier few-shot AD methods on MVTec and MPDD, with no retraining for new categories. (snippet) — [RegAD](https://arxiv.org/pdf/2207.07361)
- CAReg, the journal follow-up, uses accumulated features of each category as the registration reference instead of a single image. (snippet) — [CAReg](https://arxiv.org/html/2406.08810v1)
- Position-aware feature comparison already appears inside the logical-AD methods: SAM-LAD fits a multivariate Gaussian to matched reference features at each patch position and scores with Mahalanobis distance; UniVAD matches patches only within the same component. — [SAM-LAD](https://arxiv.org/html/2406.00625); [UniVAD](https://arxiv.org/html/2412.03342v2)

### Inferences
- The evidence that feature-level comparison beats pixel differencing is real but comes from supervised training on tens of thousands of labelled defects. It cannot be transferred as-is to a good-only, 5-20 image, many-SKU setting. What does transfer is the mechanism: features with a larger receptive field tolerate a pixel or two of misregistration that would light up a raw difference image.
- The good-only analogue is a frozen backbone (DINOv2/DINOv3 or a CNN) with per-position reference statistics (PaDiM-style Gaussian, or nearest neighbour restricted to a small spatial window around the same location). This is the minimal change to the existing DINOv2 baseline and directly targets its missing-letter blind spot.
- Trade-off: DINOv2 ViT patches are 14 px (about 2.4 mm here). Feature comparison will see a missing letter or a torn-off part easily, but a 0.3-0.5 mm nick on an edge is sub-patch and is better caught by pixel/edge comparison at full resolution. So feature differencing and pixel/edge differencing complement each other; they are not substitutes.
- A learned Siamese comparator could still be trained without real defects by synthesising them on good images (erase a letter, cut part of a stroke, erode an edge), which is what LogiCo and SALAD do at the segmentation-map level. This is a research bet, not an established result for labels.

### Gaps
- Most Siamese/template papers above were seen only as abstracts or snippets; data requirements and cross-product generalisation were not verified.
- No study found that compares frozen-feature differencing with pixel differencing in a good-only, few-shot print setting.
- DeepPCB-specific method details (dataset size, template/test pairing) were not retrieved in this session.
- RegAD/CAReg numbers on print or label data: none found.

## 4. Shape-level checks for large solid letters: binary mask versus reference mask

### Takeaway
I found no paper or vendor note about heat-transfer, vinyl or die-cut lettering inspection specifically. The closest established practice is edge/boundary comparison with explicit missing and extra edge outputs (Cognex patents and Flexible Flaw Detection), per-character difference images (old label-inspection patents), and, on the research side, the component-map statistics used by LOCO methods, which amount to "is the right amount of each component in each cell". For near-binary white-on-clear letters a mask comparison is the natural simple method, but the choice of metric (IoU, XOR area, contour distance) is engineering judgement, not something the literature settles.

### Cited Findings
- Boundary-based comparison reports three classes of boundary points (match, extra, missing) with distance, angle and contrast tolerances, then groups them into features by connectivity; it was introduced because grey-level golden-template comparison is unreliable at object edges. — [US6381366, Cognex](https://patents.google.com/patent/US6381366)
- A companion Cognex patent covers boundary feature comparison of patterns and images. (snippet) — [US6687402](https://image-ppubs.uspto.gov/dirsearch-public/print/downloadPdf/6687402)
- In-Sight Flexible Flaw Detection reports "missing edge" when a trained edge segment is not found and "extra edge" when a new one appears, and recommends combining area and edge inspection for the highest degree of verification. — [Cognex In-Sight Flaw Detection docs](https://docs.cognex.com/isvidi_161/web/en/help_isvidi/content/topics/Spreadsheet/VisionTools/FlawDetection.htm)
- An early label-inspection patent compares each character of the inspected label with the reference label and produces a difference image per character. (snippet) — [US4589141](https://image-ppubs.uspto.gov/dirsearch-public/print/downloadPdf/4589141)
- Die-cutting lines use camera systems that compare the printed image and the cut contour with a target (register between print and die line), for example Erhardt+Leimer's cut-to-mark check. (snippet) — [US11858255](https://image-ppubs.uspto.gov/dirsearch-public/print/downloadPdf/11858255); [Automate case study](https://www.automate.org/vision/case-studies/precision-up-to-the-second-decimal-place)
- Research analogues of a mask check: CSAD compares class histograms of the predicted segmentation map per grid cell with normal statistics (Mahalanobis distance); PSAD keeps a class-histogram memory bank; UniVAD adds geometric component features (area, colour, position); the Sept-2026 calibrated-fusion method counts named concepts with SAM3; LogiCo trains on "deletion" and "erasure" edits of the segmentation map. — [CSAD](https://arxiv.org/html/2408.15628); [UniVAD](https://arxiv.org/html/2412.03342v2); [Calibrated fusion](https://arxiv.org/html/2609.05091v1); [LogiCo](https://arxiv.org/html/2606.28688)
- CSAD's ablation logic for why the map must be compared per region: a global histogram loses position, so the map is split into grids. — [CSAD](https://arxiv.org/html/2408.15628)

### Inferences
- Suggested decomposition for this label (my reasoning, not a cited practice). Segment white lettering to a binary mask, align it to the SKU's reference mask (per letter, to absorb film stretch), then compute:
  - Per-letter connected-component count and area ratio versus reference: catches a whole missing letter and a large torn-off part. This is the direct fix for the baseline's blind spot.
  - XOR of test and reference masks after removing a tolerance band of 1-2 px along the reference contour, then blob analysis on what remains ("missing" blobs = reference minus test, "extra" blobs = test minus reference): catches partial transfer failures and bigger nicks.
  - Contour distance (distance transform of the reference contour sampled along the test contour, or the reverse): catches edge nicks with a threshold in mm. A robust percentile or run-length criterion is safer than max Hausdorff, which reacts to a single noisy pixel.
- IoU and Hu moments are weak for this job. On a 30-60 mm letter (roughly 175-350 px tall) a 1 mm nick changes IoU by well under 1%, and Hu moments are global shape descriptors that barely move for local damage. Local measures (blob area after XOR, contour distance) are the sensitive ones.
- Detectable nick size is bounded by resolution and by the tolerance band: at 0.17 mm/px with a 1-2 px band, expect a floor of roughly 0.3-0.5 mm depth; smaller edge defects need a sub-pixel edge fit or higher magnification.
- With 5-20 good images the reference mask can be a per-pixel vote (median) and the tolerance band can be learned from where the good masks disagree, which is the mask-domain version of the HALCON variation image.
- The segmentation step is the risk on clear film: white ink over a bright or textured background can lose contrast. Lighting/backing that gives a dark, even background behind the film matters more than the comparison metric.

### Gaps
- No literature or vendor documentation found on inspection of heat-transfer labels, vinyl lettering or stencil-like prints using mask IoU / XOR / Hausdorff. The metric recommendations above are inferences.
- No published numbers on the smallest detectable edge defect for mask comparison at a given px/mm.
- HALCON's contour-based tools (for example sub-pixel contour to model distance) were not retrieved; I cannot cite operator-level documentation for contour-distance checks.

## 5. Small text: OCV versus OCR, offline deep OCR engines, VLM reading, and whether a 2 mm (about 12 px) character is readable at 0.17 mm/px

### Takeaway
Vendor rules of thumb put reliable reading at about 20-30 px character height with strokes of at least 3 px; 10 px is quoted as an absolute floor by a few sources. A 2 mm character at 0.17 mm/px is about 12 px tall with strokes of about 1-2 px, so it sits below the reliable range: checking that the line is present, in place and roughly the right length is realistic, but reading the lot code character by character should not be promised without more pixels on that region.

### Cited Findings
- OCR returns the character string; OCV checks whether the string matches the expected text. Results depend on character count, lighting and field of view and should be confirmed on real parts. (snippet) — [Keyence blog](https://www.keyence.com/blog/read-back-marking-station-ocr-ocv-code-verification-pharma.jsp)
- Basler OCR vTool: "A character height between 20 to 30 pixels is an appropriate size range" and "Characters below 20 pixels can't be recognized reliably anymore." Text must have consistent polarity (dark-on-light is the native case; light-on-dark is inverted internally) and orientation may deviate only by a few degrees. — [Basler OCR vTool docs](https://docs.baslerweb.com/ocr-vtool)
- A3/Automate guidance: a typical character should cover about 20-25 by 20-25 pixels, the stroke of the smallest character should be at least three pixels wide, and there should be about a two-pixel gap between characters. (snippet; the page returned HTTP 403 when opened) — [Automate.org, considerations in OCR/OCV applications](https://www.automate.org/industry-insights/considerations-in-ocr-ocv-applications)
- Omron/Microscan Quadrus MINI OCR: supported character height 10 to 50 pixels, with 20 pixels the best balance of read rate, accuracy and speed. (snippet) — [Industrial Monitor Direct knowledge base](https://industrialmonitordirect.com/blogs/knowledgebase/quadrus-mini-ocr-selecting-valid-character-image-size)
- Adaptive Recognition (number-plate OCR): at least 10 pixels of height for Latin characters. (snippet) — [Adaptive Recognition input image guide](https://adaptiverecognition.com/app/uploads/DOC/Software/Carmen/brief_guide_for_input_images.pdf)
- Broadcom OCR guidance: minimum 18 pixels vertical for an upper-case Latin character. (snippet) — [Broadcom knowledge base](https://knowledge.broadcom.com/external/article?articleId=254861)
- EasyRPA OCR tuning guide: below an x-height of 10 pixels there is very little chance of accurate results. (snippet) — [EasyRPA docs](https://docs.easyrpa.eu/help/docs/Data-Analyst-Guide/OCR-Tuning-Guide/Evaluating-and-Enhancing-Image-Quality-for-OCR)
- Tesseract user report: OCR error rate correlated most strongly with the height of a capital letter in pixels. (snippet) — [tesseract-ocr Google Group](https://groups.google.com/g/tesseract-ocr/c/Wdh_JJwnw94/m/24JHDYQbBQAJ?pli=1)
- Cognex: characters should have at least 5 pixels per stroke width for OCR; for the OCV tool, stroke width should not vary by more than 10% and the font model needs a clear border of one to three stroke widths. (snippet; I could not confirm which Cognex page each statement is on) — [Cognex In-Sight read-text docs](https://docs.cognex.com/is_573/web/EN/ezb/Content/EasyBuilder/Inspect_ID_ReadText_SelectText.htm); [Cognex VisionPro OCV tool](https://docs.cognex.com/vpro_950/web/EN/help/html/59a52d12-e169-4fd7-aaa4-be4134a6ab4e.htm)
- PP-OCRv5 (paper March 2026, CVPR 2026): two-stage system with a DB detector on a PP-LCNetV3 backbone and an SVTR_LCNet recogniser; the mobile version has about 5 M parameters in total; a higher-capacity server variant exists; code and models are public. — [PP-OCRv5 paper](https://arxiv.org/html/2603.24373v1)
- PP-OCRv5 versus VLMs on OmniDocBench (edit-distance style score, lower is better): Qwen3-VL 0.026, PP-OCRv5 0.067, GOT-OCR 0.077, InternVL2 0.115, GPT-4o 0.122, Qwen2-VL 0.173. On PaddleOCR's in-house benchmark, weighted accuracy 80.1 for PP-OCRv5 versus 53.0 for PP-OCRv4. The paper says nothing about minimum text height or low-resolution text. — [PP-OCRv5 paper](https://arxiv.org/html/2603.24373v1)
- A PP-OCRv5 deployment guide exports the recogniser with input shape 3 x 48 x variable width, so text lines are resized to 48 px height before recognition. (snippet) — [PP-OCRv5 Ascend deployment guide](https://ai.gitcode.com/Ascend-SACT/PaddleOCR-PP-OCRv5-300I-Duo)
- VLM reading in an industrial loop is slow and inconsistent in published AD work: LogicAD reports a few seconds per image with GPT-4o and large differences between VLMs. — [LogicAD](https://arxiv.org/pdf/2501.01767)

### Inferences
- Arithmetic for this setup: 2 mm / 0.17 mm per px = 11.8 px character height. A normal-weight sans-serif stroke is roughly 10-15% of cap height, so 0.2-0.3 mm, or 1.2-1.8 px. Against the cited rules (20-30 px height, stroke of 3-5 px) the lot code is under-sampled by about a factor of two. Upscaling the crop before OCR helps a recogniser that resizes to 48 px internally but adds no information.
- What 12 px can support: presence of the text line, its position relative to the logo, its length and approximate character count (projection profile or connected blobs), and gross failures such as half the line missing. This is an OCV-style "is the expected print there and intact" check and can reuse the golden-template comparison from section 2 if the line content is fixed per SKU.
- What 12 px probably cannot support reliably: distinguishing similar characters (0/O, 1/I, 8/B, 6/8) in a lot code or date, or catching one broken character. If "unreadable" must mean "a human could not read it", the realistic options are (a) a second camera or a longer lens on the lot-code region to reach 20-30 px height, (b) a higher-resolution sensor, or (c) accept a presence/integrity check only. For 20-30 px on a 2 mm character the scale needs to be about 0.07-0.10 mm/px.
- If the lot code changes per batch (it contains a date), a fixed golden template for that line will not work; the check has to be either OCR against an expected string supplied by the operator/MES, or a content-agnostic integrity check (line present, stroke density per character cell within range).
- White-on-clear text is light-on-dark or low-contrast depending on the backing. Most OCR engines are trained mainly on dark-on-light text; inverting the crop and normalising contrast before OCR is a cheap step worth testing.
- Deep OCR (PP-OCRv5 mobile, 5 M parameters) is small enough for offline CPU use; that it works at 12 px is untested here and must be measured on real crops.

### Gaps
- No source gives a measured accuracy-versus-character-height curve for PP-OCRv5, EasyOCR, docTR or Tesseract at 10-15 px. No sources were retrieved at all for EasyOCR or docTR.
- No PaddleOCR release later than PP-OCRv5 was confirmed in this session; I did not check the PaddleOCR repository for a newer version.
- No evidence found on VLM (GPT-4o class, Qwen-VL) reading accuracy for 12 px industrial lot codes. The OmniDocBench figures are for document pages, not small low-contrast marks.
- The Cognex stroke-width and OCV statements and the Automate.org figures come from snippets only.
- Actual font, stroke width and contrast of the lot code on this label are unknown; the readability judgement should be re-checked on real images.

## 6. How hybrid systems combine a logical/layout check with a surface (structural) anomaly check in one pipeline

### Takeaway
Every strong LOCO method is a hybrid: one branch for local texture/surface defects, one or more branches for composition/layout, each producing its own score, with the scores normalised on held-out good images and then fused by sum, max or a soft-OR. The same pattern fits this label: keep the existing patch-level surface detector, add a layout branch (mask/template comparison per letter, plus a text-line check), calibrate each branch on good images and take the maximum.

### Cited Findings
- CSAD: patch-histogram branch on the segmentation map (logical) plus a local/global student-teacher branch (structural); the two scores are normalised separately and summed. — [CSAD](https://arxiv.org/html/2408.15628)
- SALAD: local appearance branch (EfficientAD-based) for structural defects, composition branch and global appearance branch for logical defects, followed by score fusion. — [SALAD](https://arxiv.org/html/2509.02101)
- LogSAD: patch score and interest score are standardised with statistics from normal validation images, passed through a sigmoid, and combined with the binary composition-rule score by taking the maximum. — [LogSAD](https://arxiv.org/html/2503.18325v1)
- Calibrated fusion (Sept 2026): each of five frozen branches is divided by its 99th-percentile score on normal images and the calibrated scores are fused with a p-norm soft-OR (p=6); the paper's point is that calibration and fusion, not training, give 92.5 mean AUROC with 95.9 on structural anomalies. — [Calibrated fusion](https://arxiv.org/html/2609.05091v1)
- LogiCo: anomaly maps from the component-level, patch-level and segmentation-map branches are normalised with statistics from held-out validation images (20% of training images on some datasets) and fused by element-wise maximum. — [LogiCo](https://arxiv.org/html/2606.28688)
- UniVAD: structural map (component-aware patch matching) and logical map (graph over component features plus area/colour/position) are averaged with equal weights of 0.5. — [UniVAD](https://arxiv.org/html/2412.03342v2)
- EfficientAD/GCAD pattern: a local branch for small defects and a global, bottlenecked branch for layout, both producing anomaly maps that are combined. — [LogiCo](https://arxiv.org/html/2606.28688); [CSAD](https://arxiv.org/html/2408.15628)
- Industrial counterpart: Cognex recommends running area inspection (surface defects such as scratches and stains) and edge inspection (missing/extra edges, boundary consistency) together: "Combining area and edge defects provides the highest degree of inspection verification." — [Cognex In-Sight Flaw Detection docs](https://docs.cognex.com/isvidi_161/web/en/help_isvidi/content/topics/Spreadsheet/VisionTools/FlawDetection.htm)
- Trade-off visible in the tables: branches specialised for logic tend to be weak on structure and the reverse. SAM-LAD is 95.8 logical but 85.5 structural; EfficientAD is 86.8 logical but 94.7 structural; the fused systems (CSAD, SALAD, LogiCo) are the ones above 94 on both. — [SAM-LAD](https://arxiv.org/html/2406.00625); [CSAD](https://arxiv.org/html/2408.15628); [SALAD](https://arxiv.org/html/2509.02101)

### Inferences
- Overall fit for the "betway" label, ranked by how well each family matches the constraints (good-only, 5-20 images, many SKUs, near-fixed pose):
  1. Golden-template comparison in the mask/edge domain (sections 2 and 4) is the best fit for missing letters, torn-off parts and edge nicks. It needs one to a few good images, no training, and gives explainable outputs (which letter, how many mm2 missing). Main risks: segmentation contrast on clear film and film stretch, handled by per-letter alignment and an edge tolerance band.
  2. Position-constrained feature comparison (frozen DINOv2 with per-location reference statistics, section 3) is the smallest change to the current baseline and fixes its blind spot for missing letters; it also keeps catching surface defects (scratches, stains). It is coarse (patch about 2.4 mm), so it will not see small nicks.
  3. OCV-style check on the lot-code line (section 5): presence, position and integrity are feasible at about 12 px; true reading needs more pixels.
  4. LOCO-style logical AD models (section 1) are the poorest fit as drop-in tools: the accurate ones need per-category training on hundreds of images, the few-shot ones are slow, depend on heavy or cloud models, and score well below production needs. Their value here is the design pattern, not the code.
- A workable hybrid for this project, following the fusion pattern above: (a) rectify and align per letter; (b) layout branch = mask comparison per letter and per text line, giving area-missing, extra-area and contour-distance scores; (c) surface branch = existing DINOv2 patch detector, made position-aware; (d) text branch = line presence/integrity, optional OCR against an expected string; (e) calibrate each score on the good images (for example divide by a high percentile or use mean plus k sigma) and take the max, reporting which branch fired.
- With only 5-20 good images, calibration statistics are noisy. Leave-one-out scoring across the good images (score each good image against a reference built from the others) is the obvious way to get per-branch normal score distributions without holding images out; the cited papers assume a separate validation set and do not test this.
- Using physical units for the layout branch (mm2 of missing letter area, mm of contour deviation) avoids per-SKU score calibration for that branch and lets one acceptance spec apply to all SKUs, in line with per-SKU parameter files for anything that must differ.

### Gaps
- None of the cited fusion schemes was evaluated with fewer than about 100 normal images for calibration; how stable percentile or z-score calibration is at 5-20 images is unknown.
- No published hybrid pipeline for printed labels that combines mask/template comparison with a foundation-model surface detector was found; the proposed combination is an inference from the LOCO literature and vendor tool design.
- No head-to-head study of fusion rules (sum versus max versus soft-OR) outside the single 2026 preprint.
